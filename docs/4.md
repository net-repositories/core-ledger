# Спринт 4: Redis (Кэширование и Идемпотентность), Rate Limiting и JWT-авторизация

В высоконагруженном финтехе чтение баланса происходит в 20–50 раз чаще, чем списание денег (клиенты постоянно обновляют экран приложения). Дергать PostgreSQL на каждый GET /api/accounts/{id} дорого. Плюс нам нужно защитить API от DDoS/брутфорса и привязать счета к реальным авторизованным пользователям (чтобы Вася не мог перевести деньги со счета Пети).

## 1. Инфраструктура (Docker Compose и пакеты)

- Добавьте Redis (redis:7-alpine) в docker-compose.yml.
- Подключите Microsoft.Extensions.Caching.StackExchangeRedis (и StackExchange.Redis, если потребуется прямой доступ) и Microsoft.AspNetCore.Authentication.JwtBearer.

## 2. Кэширование балансов (Cache-Aside + Инвалидация)

- Создайте абстракцию ICacheService (в Application) и ее реализацию на базе IDistributedCache / Redis (в Infrastructure).
- Чтение (GetAccountByIdAsync): Сначала ищем счет в Redis по ключу account:{id} (TTL — например, 5 минут). Если в кэше пусто — идем в PostgreSQL, кладем в Redis и отдаем клиенту.
- Инвалидация (Критично для финтеха!): После успешного коммита транзакции (Deposit, Withdraw, Transfer) в TransactionService (или через консьюмера TransactionCompletedEvent — подумайте, что надежнее для пользователя, который сразу после перевода делает GET!) удаляйте закэшированные ключи затронутых счетов из Redis.

## 3. Защита от спама (Rate Limiting)

В .NET 7/8+ есть встроенный AddRateLimiter:

- Настройте Fixed Window или Sliding Window лимитер на эндпоинты транзакций (POST /api/transactions/*) — например, не более 10 запросов в минуту на одного пользователя (или IP), при превышении возвращать 429 Too Many Requests.

## 4. Безопасность: JWT и проверка владельца (Ownership)

Закрываем дыру в безопасности, когда любой может списать деньги с любого AccountId:

- Добавьте эндпоинт POST /api/auth/login (можно упрощенно: по Email + паролю или просто генерация JWT по UserId/Email для тестирования, чтобы не тратить время на полноценный Identity). В токен зашейте ClaimTypes.NameIdentifier = UserId.
- Закройте контроллеры атрибутом [Authorize].
- Создайте сервис ICurrentUserService, который достает UserId из HttpContext.User.
- Проверка прав: В WithdrawAsync и TransferAsync убедитесь, что fromAccount.UserId == currentUser.UserId. Если пользователь пытается списать деньги с чужого счета — бросайте ForbiddenException (HTTP 403 Forbidden).
