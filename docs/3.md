# Спринт 3: Transactional Outbox, RabbitMQ (MassTransit) и Аудит/Уведомления

В реальном финтехе после проведения транзакции нужно уведомить другие сервисы: отправить пуш клиенту, пересчитать кэш-аналитику или запустить антифрод-проверку.
Главная проблема (Dual Write): Если мы сделаем await dbTx.CommitAsync(), а следующей строчкой отправим сообщение в RabbitMQ (await publishEndpoint.Publish(...)), брокер может быть временно недоступен. Деньги списались, а событие потерялось.
Решаем эту проблему с помощью паттерна Transactional Outbox и связки RabbitMQ + MassTransit.

## 1. Инфраструктура (Docker Compose)

- Добавьте в docker-compose.yml контейнер с RabbitMQ (образ rabbitmq:3-management, чтобы была админка на порту 15672).
- Подключите пакеты MassTransit.RabbitMQ и MassTransit.EntityFrameworkCore.

## 2. Контракты событий (Integration Events)

Создайте контракты (например, в отдельном пространстве имен или проекте CoreLedger.Contracts / Application.Events):

- TransactionCompletedEvent — содержит TransactionId, FromAccountId, ToAccountId, Amount, Currency, Type, OccurredAt.

## 3. Настройка Transactional Outbox в MassTransit

Вместо ручного создания таблицы outbox_messages и фонового воркера используйте встроенный в MassTransit EF Core Outbox (это стандарт индустрии на .NET):

- Добавьте в AppDbContext системные сущности MassTransit (builder.AddInboxStateEntity(), builder.AddOutboxMessageEntity(), builder.AddOutboxStateEntity()) и создайте новую миграцию.
- В конфигурации MassTransit (AddMassTransit) включите AddEntityFrameworkOutbox<AppDbContext>(o => { o.UsePostgres(); o.UseBusOutbox(); }).
- В TransactionService перед вызовом SaveChangesAsync() и dbTx.CommitAsync() вызовите await publishEndpoint.Publish(new TransactionCompletedEvent(...), ct). (Благодаря Outbox сообщение сохранится в БД в той же самой транзакции, что и изменение баланса, а фоновый процесс MassTransit сам доставит его в RabbitMQ).

## 4. Потребитель (Consumer) — Сервис уведомлений / Антифрод

Создайте тестового консьюмера TransactionCompletedConsumer : IConsumer<TransactionCompletedEvent>:

- Пусть он логирует через ILogger имитацию отправки уведомления клиенту.
- Антифрод-правило: Если сумма транзакции (Amount) больше 100_000, консьюмер должен дополнительно писать LogWarning("ALERT: High-value transaction detected...").
- Настройте политику повторных попыток (UseMessageRetry) на случай временных сбоев при обработке сообщения.
